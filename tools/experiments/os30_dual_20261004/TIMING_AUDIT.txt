Follow-up: direct raw FP trap classification
------------------------------------------
The stage1 split's isolated critical path was not its standalone decompressor
illegal flag. At 86.03 MHz it passed RAW instruction bit1 -> expanded opcode ->
DecoderPlugin fp_triggered -> TRAP bypass -> PC halt -> fetch valid enable.
The control-factored version reached89.13 MHz, with RAW bits14/11 -> expanded
opcode -> fp_triggered -> trap pending register enable as its critical path.
Moving only DECOMPRESSION_FAULT back to decode0 would restore two old enabled
registers without changing cycles, but would leave this measured cone intact.

A smaller candidate computes the two FP trap classification flags directly
from the already registered raw instruction. For compressed RV32F instructions,
NEED_RM is always false, and NEED_FPU is true for raw {quadrant,funct3} values
3,5,7,19,23. Value5 preserves the existing C.FSD classification: the configured
RV32F ISA rejects it later, but this decompressor's own illegal flag does not.
For ordinary instructions, evaluate the unchanged generated classification
expression on RAW, which equals the expanded instruction. Rounding-mode
bits may also come from RAW: compressed NEED_RM is zero, while ordinary
instructions have the same bits. Dynamic FP enable and frm remain live in
the same decoder stage; no state or cycle is added.

check_raw_fp_flags.py extracts the actual generated classification cones and
the existing actual generated RVC cone. Its artifacts are at
docs/measurements/os30-dual-20261004/raw-fp-flags-audit-v1/.
It passed65,536 exhaustive low16-bit inputs plus1,000,000 random32-bit inputs,
with all16 FP-enable/frm states per input. It compares the flags whenever the
RVC output is defined and compares the resulting fault/FP-trap OR for every
input including illegal encodings. Existing DECOMPRESSION_FAULT unconditionally
forces ISA LEGAL false, masking decompressor instruction don't-cares.
Only fp_triggered consumes these NEED_FPU/RM flags in this generated profile.
The generator agent owns candidate emission and exact-profile guards; the
validation agent owns full CPU trap/stall/kernel regressions. The extracted
proof establishes this combinational rewrite, not final FPGA timing or FPS.
