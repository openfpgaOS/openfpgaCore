F24 admission and canonical-boundary review

Exact frozen native replay: 354 original G_VTX calls per interval, 326 actual hardware LOADs. The warm interval queues 76 asynchronous tasks. Its 250 legacy hardware LOADs comprise 171 canonical dead-suffix rejections, 48 material-admission rejections, 22 prior-repair routing hints, 2 topology-cache probe exhaustion cases, and 7 LOADs with no adjacent TRI commands. There are also 27 mutable-command CPU transforms and one suffix-rejected CPU transform.

The ELF contains 320 strict immutable own-slot VTX/TRI tasks per interval. Two cannot enter the current 16-probe topology cache. Of the 172 compiled dead-suffix rejections, 162 stop at ENDDL, 2 at MOVEMEM, 6 at TEXTURE, and 2 at SETTIMG. The old proof stops at every state/list/end command; it does not establish that all those vertices are semantically live after the boundary. Exact final admission counters establish the remaining 48 dead-topology tasks per interval as material rejections, but the trace does not distinguish cold material from shader/alpha/LOD subtypes. No dynamic LOAD/source admission rejection was recorded.

A cached vector of immutable subjob descriptors plus one context/group submission can genuinely remove per-subjob CPU display-list dispatch, topology lookup, material resolution, source lookup and context/descriptor emission. The producer must skip those calls using a cached block end pointer, not merely combine existing kicks. Group bounds must stop before state changes, calls/returns and uncertain canonical lifetimes unless the exit state has an explicit owner. Descriptor/source generation must remain immutable until true group completion, even if a priority legacy lease is granted earlier.

Aggregate raw handback can expand coverage beyond the dead-suffix gate, but it needs additional ownership rules. geometry_raw_load preserves successful rows outside dest..dest+count and tracks valid_slots. With all dest0 LOADs and unchanged transform/light/UV/fog context, the group's touched union is the prefix [0,maxcount), with each final slot taken from the last descriptor whose count includes it. The CPU can retain incoming slots above that union, mark the union's GPU vertex cache stale, and defer canonical copies/fog using one captured coefficient pair. Smaller internal LOADs do not require repeated fog work because the coefficients and relevant material convention stay identical.

Two hazards prevent unconditional maxcount handback. A failed raw LOAD invalidates its rows, and the current pure CPU repair helper does not write reconstructed results into raw BRAM. Missing final rows need explicit canonical reconstruction from immutable per-slot source provenance. In addition, priority legacy LOADs can overwrite retained rows between group subjobs; a later smaller group LOAD cannot repair those high slots merely by restoring matrix context. A broad handback design must exclude legacy writes across the group, preserve/restore its raw rows, or reconstruct final canonical values. Ordinary clip/cull/packet fallback after successful raw LOAD does not by itself invalidate the raw rows.

The smallest first implementation is cached multi-subjob prefix batching under the existing per-task dead-slot proof, with current repair and priority handoffs preserved. Broader canonical handback is a separate scope decision requiring the above tests and a measured native full-frame comparison. Neither grouping counts nor current charged function costs predict a speedup.
